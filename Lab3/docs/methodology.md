# Розвиток V-моделі: ітерації з безперервною локальною перевіркою

У власній ЛР №2 (Lab2/docs/methodology.md у репозиторії) використано V-модель.
У ЛР №3 збережено відповідність вимог тестам, але робочі прирости створюються
короткими ітераціями: ядро → інтерфейс → аналіз → документація.

1. Вимоги й аналітичний еталон — перевірка підстановкою.
2. Стратегії та парсер — перевірка кроків, точності, помилкових виразів.
3. Інтерфейс і анімація — браузерні сценарії та скріншоти.
4. Аналіз порядку, стійкості, системи — таблиці фактичних запусків.
5. Оптимізація і документація — повторні перевірки зміненого компонента.

Це ітеративно-інкрементний підхід із практиками автоматизованого тестування,
малих приростів і рефакторингу. Формальний процес TDD не заявляється:
частина тестів написана після першої реалізації.

Ризики: помилка h/2 у РК4 → тест порядку та навмисна мутація;
небезпечне введення → парсер без eval; нестійкість → окремий сценарій;
зайва робота на кадрі → кешування похибок після побудови моделі.
